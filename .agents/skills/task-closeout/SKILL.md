# Task Closeout

## 1. 输入

1. 当前任务目标。
2. 本轮实际改动。
3. 已执行验证。
4. 未执行验证及客观原因。
5. 当前工作树状态。
6. 用户是否明确要求提交、部署或上线。

## 2. 强制边界

1. 不默认部署测试环境。
2. 不默认上线正式环境。
3. 不暂存无关文件。
4. 不回退用户未授权改动。
5. 不把“请你整体测一下”作为默认收尾。
6. 不把生产、支付、账号、权限、密钥或数据操作混进普通收尾。
7. 不把正式收尾规则反向施加给普通功能交付，不因进入本 skill 重跑已经有效的构建、测试或真机验收。

## 3. 步骤

1. 执行 `git status --short`，区分本轮改动和既有改动。
2. 汇总本轮改动范围。
3. 复用本轮已完成的有效验证。
4. 收尾阶段不改业务代码；若用户另外要求修复，退出收尾流程，按普通功能切片施工和验证。
5. 只有里程碑、交接或发布状态发生变化时才更新 `docs/progress.md`；验证矩阵、阶段方案和规则文档只在其事实本身变化时更新。
6. 清理本轮产生的临时产物，但不得删除用户文件或无关改动。
7. 执行本轮相关文件 `git diff --check`；仅在修改 skill 时执行 `check-skills`，修改项目总纲或验证入口时执行 `check-project-ready`。已初始化项目不执行模板快检。
8. 若用户要求提交，只暂存本轮相关文件并提交。
9. 输出交付说明。

## 4. 交付说明

按当前动作只包含有意义的项目：

1. 改动摘要。
2. 验证命令与结果。
3. 与本次正式收尾有关的未验证项。
4. 涉及提交时提供提交哈希或未提交原因。
5. 涉及应用运行、部署或发布时提供对应状态。
6. 尚未完成的人工门禁。

## 5. Dry Run

当用户要求“收尾方案”“dry-run 收尾”或当前会话不能提交时，只输出将执行的步骤、预计暂存文件、需要复用或补跑的验证、不会部署 / 不会上线的状态，不执行提交。
