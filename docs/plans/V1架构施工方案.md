# V1 架构施工方案

## 1. 施工目标 (Objective)

1. 在 Android 9 `S56_HQX` 上实现不依赖 root、ADB、手机或电脑的轻量右侧第三方应用抽屉。
2. V1 完整闭环包含：开机恢复、右侧触发、跟手抽屉、应用枚举与启动、拖拽排序、原生卸载、主动 APK 扫描与原生安装、返回首页、媒体键和简单音量。
3. 本文是已确认的业务施工物理蓝图；后续必须拆成可独立运行和验收的小阶段，严格按本文边界施工。
4. 阶段交付标准：本阶段所有标记为“必须通过”的自动化、构建、Debug 覆盖安装和最短真机用例 100% 通过；完整 V1 交付前仍须关闭本文全部 V1 门禁，任何必过项失败均代表对应阶段不达标。

## 2. 根因与物理定位 (Root Cause & Anchors)

1. 原厂应用中心不能完整展示用户安装应用，问题属于独立应用目录和系统适配层，不能通过修改原厂桌面或 `03歌词` 解决。
2. 当前工程只有无权限启动壳：`app/src/main/java/com/tcrrry/desktop/MainActivity.kt` 与对应 Android 资源；尚无悬浮服务、包查询、排序、安装或卸载业务。
3. Android 系统能力入口由适配器独占：WindowManager、PackageManager、SharedPreferences、StorageManager/SAF、系统 Intent、AudioManager 和系统广播不得散落到 View 或领域模型。
4. 车机只读探测已证明 launcher、HOME、系统安装器、系统卸载器、未知来源授权页和公共外部卷入口存在；证据见 `docs/testing/车机能力验证记录.md`。这不等于最终交互已经验证。

## 3. 技术栈与依赖

1. 保持单 `app` 模块、Kotlin、XML Views、Android Gradle Plugin `8.2.2`、Gradle `8.2`、Java 17。
2. V1 只新增以下运行依赖：
   - `androidx.core:core-ktx:1.12.0`：FileProvider、Context 兼容入口与 Kotlin 扩展。
   - `androidx.recyclerview:recyclerview:1.3.2`：四列网格与经过验证的 `ItemTouchHelper` 拖拽引擎。
   - `org.jetbrains.kotlinx:kotlinx-coroutines-android:1.8.1`：可取消的包查询、APK 扫描和事件合并。
3. 不引入 Compose、依赖注入框架、数据库、图片框架、网络库或应用商店 SDK。
4. 单元测试使用现有 JUnit `4.13.2`；真机自动化确有需要时再新增 AndroidX Test 依赖，不为占位提前扩张依赖面。

## 5. 编码与文件头锚点

1. 所有 Kotlin 新文件以现有 `MainActivity.kt` 的 UTF-8 文件和 `package com.tcrrry.desktop` 为来源锚点；子目录只追加 ASCII 包段，例如 `.overlay`、`.apps`，禁止中文标识符和手敲其它项目命名空间。
2. 所有布局与 Manifest/XML 新文件复制现有 `app/src/main/AndroidManifest.xml` 的 XML 声明 `<?xml version="1.0" encoding="utf-8"?>`；资源命名只用小写 ASCII 下划线。
3. 中文用户文案从现有 `app/src/main/res/values/strings.xml` 同源编辑，编码保持 UTF-8；禁止从终端乱码、截图或 Unicode 转义重建。
4. 每增加一组结构性文件后立即执行：`node scripts/check-android-config.mjs`、`./scripts/gradlew-jdk17.sh compileDebugKotlin processDebugResources`；未通过不得继续扩写下一组。

## 6. 抽屉窗口与几何

### 6.1 固定常量

| 常量 | 数值 |
|---|---:|
| 屏幕 | `1920 x 1080 px` |
| 面板展开矩形 | `x=1290..1890, y=90..900` |
| 面板宽高 | `600 x 810 px` |
| 面板视觉移动距离 | `600 px` |
| 收起触发窗 | `x=1870..1930, y=90..900`，屏内有效 `50 px` |
| 展开触发窗 | `x=1260..1320, y=90..900` |
| 触发窗宽高 | `60 x 810 px` |
| 把手线 | `6 x 150 px`，容器内 `x=27..33, y=330..480`，全局 `y=420..570` |
| 把手初始不透明度 | `0.28`，纯色细竖线，不使用按钮底板 |
| 停靠动画 | `200 ms`，Android `DecelerateInterpolator(1.5f)` |

### 6.2 两窗口实现

1. 触发窗始终存在，使用 `TYPE_APPLICATION_OVERLAY`、`PixelFormat.TRANSLUCENT`、`TOP|START` 和 `FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL | FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_NO_LIMITS`；`FLAG_LAYOUT_IN_SCREEN` 保证 x/y 以物理屏幕为坐标基准，不把状态栏下方误当作 y=0。
2. 关闭稳定态只保留触发窗；面板 Window 和应用网格必须已从 WindowManager 移除。
3. 方向锁定为打开手势后，才创建面板 Window。面板 Window 固定在 `x=1290, y=90, 600 x 810`，其内容 View 在自身裁剪区域内从 `translationX=600` 跟手移动到 `0`，视觉移动恰好 `600 px`。
4. 面板在拖动/停靠时带 `FLAG_NOT_TOUCHABLE`，避免透明或运动区域吞掉地图事件；到达展开稳定态后才移除该标志。关闭动画结束立即移除 Window、Adapter 和扫描任务。
5. 触发窗位置由 `round(1870 - 610 * openDistancePx / 600)` 计算：关闭端点精确为 `1870`，展开端点精确为 `1260`。面板运动仍严格为 `600 px`，额外 `10 px` 仅用于满足两端触发区的给定坐标。
6. 每个输入帧只更新内存位移、面板内容 `translationX` 和触发窗 x；WindowManager 的触发窗位置更新通过 Choreographer 合并为每帧最多一次。
7. 面板 Window 与触发 Window 均不申请系统级窗口类型；`TYPE_APPLICATION_OVERLAY` 的系统排序负责让状态栏和高优先级安全窗口处于更高层，最终必须用倒车影像/安全警告真机 smoke 证明。
8. 面板是后添加窗口；打开停靠完成且当前触摸序列结束后，必须移除并重新添加触发窗，使其位于同应用面板之上。这样展开触发区与面板重叠的 `x=1290..1320` 仍由触发窗接收回拉手势；不得在进行中的 MotionEvent 序列里重建触发窗。
9. Android 无法把落在触发窗自身范围内的触摸继续分发给下层地图；`FLAG_NOT_TOUCH_MODAL` 只保证窗外触摸不被拦截。因此关闭态屏内 `x=1870..1920` 会由触发窗占用，地图验收必须测量其右侧按钮在该区域之外剩余的真实可点击面积，不能宣称触发区内可穿透。

## 7. 手势状态流与阈值

1. `openDistancePx` 唯一范围为 `0..600`：`0=CLOSED`，`600=OPEN`；任何计算先 clamp 再渲染。
2. `ACTION_DOWN` 记录当前位移和稳定来源，不创建动画。移动超过系统 `scaledTouchSlop` 且水平距离不小于垂直距离的 `1.2` 倍时锁定水平手势；垂直优先则取消本轮开合并消费到本次输入结束。Android 不会把已经命中触发窗的同一事件序列重新投递给地图，禁止在实现或验收中承诺这种转交。
3. 关闭态只接受向左位移；展开态只接受向右回拉。锁定后面板位移与手指水平位移一比一，不使用速度加速、阻尼或橡皮筋效果。
4. 从展开态回拉：`closePullPx > 100` 时关闭；`closePullPx <= 100` 时恢复展开。恰好 `100 px` 不关闭。
5. 从关闭态打开：松手时 `openDistancePx >= 300` 展开，`< 300` 关闭。
6. 动画被新手势打断、进程恢复遇到中间态或状态来源不明时：`openDistancePx >= 300` 展开，`< 300` 关闭。
7. `ACTION_CANCEL` 返回本轮手势开始前的稳定态；服务重建或动画异常才使用第 6 条中点规则。
8. 停靠动画期间的新 `ACTION_DOWN` 先取消 Animator，再从当前位移继续；禁止跳回端点后重开动画。

## 8. 应用目录、主入口与排序

### 8.1 枚举规则

1. 在 `Dispatchers.IO` 使用 `ACTION_MAIN + CATEGORY_LAUNCHER` 调用 `queryIntentActivities`；不查询全部 package，不申请 `QUERY_ALL_PACKAGES`。
2. 排除 `ApplicationInfo.FLAG_SYSTEM` 或 `FLAG_UPDATED_SYSTEM_APP` 任一命中的包，以及 disabled 应用、disabled Activity 和无有效组件项。
3. 按 `packageName` 分组，每包只保留一个入口：优先选择 `getLaunchIntentForPackage` 返回且存在于候选集的组件；否则按 `priority` 降序、`preferredOrder` 降序、完整组件名升序取第一项。
4. 显示名使用选中 `ResolveInfo.loadLabel`，空值回退 Application label，再回退包名；排序身份始终只用包名，不用本地化名称。
5. `AppEntry` 至少包含：`packageName`、扁平化 `componentName`、`label`、`firstInstallTime`、`lastUpdateTime`、`isSelf` 和 `iconKey`；领域模型不得持有 Drawable/Bitmap/Context。
6. `isSelf` 只允许精确比较 `com.tcrrry.desktop`，目录合并时必须排除 `isSelf=true` 的条目，且不向其提供自卸载入口；不得按签名、开发者或 `com.tcrrry` 前缀过滤，确保 `03歌词` 走普通规则。

### 8.2 持久化与合并

1. 使用私有 SharedPreferences 文件 `app_order_v1`，键 `ordered_apps_json`。
2. JSON 格式固定为 `{"schemaVersion":1,"entries":[{"packageName":"...","firstInstallTime":0}]}`，使用 Android `org.json` 解析，不手工拼接或拆字符串。
3. 合并算法：先按存储顺序保留“当前仍存在且 `firstInstallTime` 相同”的条目，再按本次 PackageManager 查询的稳定组件顺序追加其余条目。
4. 应用更新不改变 `firstInstallTime`，因此保持位置；卸载移除存储条目；卸载后重装的 `firstInstallTime` 改变，因此旧身份失效并追加末尾。
5. 损坏 JSON、重复包名或非法时间不崩溃：丢弃非法条目、记录不含个人数据的计数日志，并用当前查询结果重建一次。
6. 拖拽只改内存快照；普通松手仅当顺序改变时调用一次 `SharedPreferences.Editor.apply()`。包事件或冷启动合并发生变化时也只写一次。

### 8.3 包变化事件

1. Service 存活期动态监听 `PACKAGE_ADDED`、`PACKAGE_REMOVED`、`PACKAGE_REPLACED`、`PACKAGE_CHANGED`、`EXTERNAL_APPLICATIONS_AVAILABLE` 和 `EXTERNAL_APPLICATIONS_UNAVAILABLE`。
2. 事件只设置 dirty，不在 BroadcastReceiver 内查询包或加载图标；`500 ms` 静默窗口后合并刷新一次。
3. `EXTRA_REPLACING=true` 的移除/添加组合按更新处理；最终仍以 PackageManager 查询和 `firstInstallTime` 合并结果为真值。
4. 拖拽期间到达的事件延迟到拖拽结束；卸载系统页返回后，取消时无移除广播，成功时包移除广播负责删除图标。

## 9. 网格、拖拽和图标

1. 使用 `GridLayoutManager(4)`；面板中央网格左内边距 `36 px`、右内边距 `12 px`、列间距 `8 px`，每列稳定宽度 `132 px`。
2. 应用 cell 初始高度 `154 px`，图标固定 `84 x 84 px`，名称最多两行、`20sp`、末尾省略；实机截图可调整一次，但调整后同步本文常量与截图验收基线。
3. 顶部 `80 px` 为固定“安装 APK”入口，底部 `108 px` 为固定快捷控制；二者不进入 RecyclerView，也不参与排序。中央剩余 `622 px` 可滚动。
4. 长按由 ItemTouchHelper 进入拖拽；`onMove` 只交换内存列表并让 RecyclerView 执行默认位移动画，不写磁盘。
5. 拖拽开始保存完整顺序快照，底部快捷区原位替换为 `108 px` 高卸载目标；拖动项中心点进入目标矩形即命中，离开即取消命中。
6. 普通松手：若顺序变化，写入一次；未变化不写。`ACTION_CANCEL`：恢复快照且不写。
7. 卸载松手：先恢复拖拽前快照且不写，再关闭抽屉并发起系统 `ACTION_DELETE package:`。用户取消时原位置已恢复；成功时包移除广播完成删除和一次持久化。
8. 图标缓存键为 `packageName:lastUpdateTime:sizePx:densityDpi`，只保存 `84 x 84` ARGB Bitmap，LRU 上限 `8 MiB`；应用更新删除该包旧键，`onTrimMemory` 按等级减半或清空。

## 10. 应用启动与系统动作

1. 点击应用后立即禁用重复点击并请求关闭抽屉；只有关闭动画结束、Panel Window 已移除后才能调用显式 ComponentName 启动。
2. 启动 Intent 使用查询时保存的组件与 `FLAG_ACTIVITY_NEW_TASK`；组件失效时只刷新该包并提示“应用暂时无法打开”，不退回隐式全包猜测。
3. 返回首页使用 `ACTION_MAIN + CATEGORY_HOME + FLAG_ACTIVITY_NEW_TASK`；不硬编码车机 launcher 包名。
4. 原生卸载使用 `ACTION_DELETE` 与 `package:` URI；不自行删除、不调用 shell、不监听私有安装器接口。
5. 所有系统 Intent 先 `resolveActivity`；没有处理器时显示面向任务的短提示，Service 和触发条继续运行。

## 11. APK 安装与存储

1. 固定安装入口先关闭抽屉，再启动非导出的 `ApkInstallActivity`；只有该 Activity 处于前台时才扫描，`onStop` 立即取消并丢弃扫描结果。
2. Android 9 系统 Download 使用 `READ_EXTERNAL_STORAGE` 运行时授权后扫描；只读取用户主动进入页面时的文件树，不注册 FileObserver。
3. U 盘/外部卷通过 `StorageManager.storageVolumes` 识别；首次由用户触发 `StorageVolume.createAccessIntent(null)` 进入系统 SAF 授权，持久化 tree URI。未授权卷不使用隐藏路径或反射绕过。
4. 对 Download 与已授权 tree URI 进行单协程、顺序、可取消的广度优先扫描；每处理一个目录检查取消，忽略不可读项，只接受普通文件且扩展名大小写不敏感等于 `.apk`。
5. 扫描结果按 `lastModified` 降序、显示名升序稳定排序，以 URI 去重；不后台缓存、不联网、不读取 APK 内部大图标。
6. 直接文件通过 `FileProvider` 转为 `content://`；SAF 文件沿用原 URI。系统安装 Intent 使用 MIME `application/vnd.android.package-archive` 与临时读授权。
7. 点击前调用 `canRequestPackageInstalls()`；未授权则进入 `MANAGE_UNKNOWN_APP_SOURCES package:com.tcrrry.desktop`，返回后重新判断，不假定授权成功。
8. 同包更新、签名冲突、版本降级、损坏文件和用户取消均由系统安装器判断；本应用只等包变化广播刷新目录。

## 12. 快捷控制

1. 返回首页按第 10 节公开 HOME Intent 实现。
2. 上一首、播放/暂停、下一首使用 `AudioManager.dispatchMediaKeyEvent`，每次严格发送同一 keyCode 的 `ACTION_DOWN` 后 `ACTION_UP`；不使用无障碍或 shell 注入。
3. 音量使用 `AudioManager.adjustStreamVolume(STREAM_MUSIC, ADJUST_LOWER/RAISE, FLAG_SHOW_UI)`；不写固定音量值，不控制通话或车辆提示音流。
4. 媒体键在当前车机固件上的最终效果尚未写操作验证，属于实施后的必须通过真机用例。若公开 API 被固件拒绝或无目标响应，停止该适配器施工并回到架构确认；禁止自行接入车厂私有广播。

## 13. 开机、服务与恢复

1. `MainActivity` 只负责解释并引导 `SYSTEM_ALERT_WINDOW`；`onResume` 重新检查，授权后调用 `startForegroundService` 并结束 Activity。
2. `OverlayService` 在启动后 `5 s` 内创建低重要级通知渠道并 `startForeground`，返回 `START_STICKY`；通知只说明“03桌面正在运行”，不伪装系统服务。
3. `BootReceiver` 只处理 `BOOT_COMPLETED` 和 `MY_PACKAGE_REPLACED`；仅当 `Settings.canDrawOverlays` 为真时启动服务，否则不后台弹权限页。
4. 服务重建默认恢复 CLOSED，仅创建触发窗；不持久化中间动画或 OPEN 状态，避免开机直接遮挡地图。
5. 权限被撤销、WindowManager 添加失败或 View 异常时立即释放所有本应用窗口并停止前台服务；不得影响其它应用触摸。
6. 不使用定时 Alarm、Job、WorkManager、忽略电池优化或高频自拉活。`START_STICKY + BOOT_COMPLETED + MY_PACKAGE_REPLACED` 是 V1 允许的恢复边界。

## 14. Manifest 权限白名单

| 权限 | 使用时机 | 用户门禁 |
