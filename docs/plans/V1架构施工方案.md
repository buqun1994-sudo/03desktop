# V1 架构施工方案

## 1. 施工目标 (Objective)

1. 在 Android 9 `S56_HQX` 上实现不依赖 root、ADB、手机或电脑的轻量右侧第三方应用抽屉。
2. V1 完整闭环包含：开机恢复、右侧触发、轻点全局返回、跟手抽屉、窗外点击自动收起、应用枚举与启动、拖拽排序、原生卸载、内置 Download APK 安装，以及可选增强文件管理器直达 U 盘。
3. 本文是已确认的业务架构与物理边界蓝图，不再规定日常施工对话、交付批次或每轮必跑验证；当前协作节奏以根 `AGENTS.md` 和 `docs/testing/验证矩阵.md` 为准。
4. V1 能力按可独立运行的最小功能切片施工。任一切片完成基础机器检查后即可交给用户手动验收，不等待其它 V1 能力，也不要求在同一对话连续完成。
5. 第 16 节是里程碑、提交/发布准备或用户明确要求完整验证时使用的验收清单，不是普通功能切片的交付门禁。

## 2. 根因与物理定位 (Root Cause & Anchors)

1. 原厂应用中心不能完整展示用户安装应用，问题属于独立应用目录和系统适配层，不能通过修改原厂桌面或 `03歌词` 解决。
2. 当前工程已经形成悬浮抽屉、应用目录、排序、启动与卸载主链；`MainActivity` 仅作为无界面的服务启动入口。
3. Android 系统能力入口由适配器独占：WindowManager、PackageManager、SharedPreferences、系统 Intent、系统广播和单动作 AccessibilityService 不得散落到 View 或领域模型。
4. 车机探测已证明 launcher、Download、系统安装器、未知来源授权、系统卸载器和公共可移动卷可用；增强文件管理器的显式 U 盘动作已在真实 `/storage/udisk` 上完成运行验证。证据见 `docs/testing/车机能力验证记录.md`。

## 3. 技术栈与依赖

1. 保持单 `app` 模块、Kotlin、XML Views、Android Gradle Plugin `8.2.2`、Gradle `8.2`、Java 17。
2. V1 只新增以下运行依赖：
   - `androidx.core:core-ktx:1.12.0`：前台服务兼容入口与 Kotlin 扩展。
   - `androidx.recyclerview:recyclerview:1.3.2`：四列网格与经过验证的 `ItemTouchHelper` 拖拽引擎。
   - `org.jetbrains.kotlinx:kotlinx-coroutines-android:1.8.1`：可取消的包查询和事件合并。
3. 不引入 Compose、依赖注入框架、数据库、图片框架、网络库或应用商店 SDK。
4. 单元测试使用现有 JUnit `4.13.2`；真机自动化确有需要时再新增 AndroidX Test 依赖，不为占位提前扩张依赖面。

## 5. 编码与文件头锚点

1. 所有 Kotlin 新文件以现有 `MainActivity.kt` 的 UTF-8 文件和 `package com.tcrrry.desktop` 为来源锚点；子目录只追加 ASCII 包段，例如 `.overlay`、`.apps`，禁止中文标识符和手敲其它项目命名空间。
2. 所有布局与 Manifest/XML 新文件复制现有 `app/src/main/AndroidManifest.xml` 的 XML 声明 `<?xml version="1.0" encoding="utf-8"?>`；资源命名只用小写 ASCII 下划线。
3. 中文用户文案从现有 `app/src/main/res/values/strings.xml` 同源编辑，编码保持 UTF-8；禁止从终端乱码、截图或 Unicode 转义重建。
4. 一个功能切片内可连续完成相互依赖的结构性文件，切片结束时统一执行 `assembleDebug`；若命名空间、类型归属或资源处理出现错误，先修复再交付。

## 6. 抽屉窗口与几何

### 6.1 固定常量

| 常量 | 数值 |
|---|---:|
| 屏幕 | `1920 x 1080 px` |
| 面板稳定展开矩形 | `x=1290..1890, y=90..900`，右侧保留 `30 px` |
| 面板内容宽高 | `600 x 810 px` |
| 拖拽运动容器 | `x=1290..1920, y=90..900`，`630 x 810 px`；只在运动阶段延伸到物理右边缘 |
| 面板视觉移动距离 | `610 px`；手势状态同为 `0..610 px`，保持 1:1 跟手 |
| 收起触发窗 | `x=1870..1930, y=90..900`，屏内有效 `50 px` |
| 展开触发窗 | `x=1260..1320, y=90..900` |
| 触发窗宽高 | `60 x 810 px` |
| 把手线 | `6 x 150 px`，圆角半径 `3 px`；触发窗内 `x=32..38, y=330..480`，全局 `y=420..570` |
| 把手主题色 | 浅色 `#2B000000`、深色 `#2BFFFFFF`，主 alpha `43/255`，不使用按钮底板 |
| 停靠动画 | `200 ms`，Android `DecelerateInterpolator(1.5f)` |

### 6.2 两窗口实现

1. 触发窗始终存在，使用 `TYPE_APPLICATION_OVERLAY`、`PixelFormat.TRANSLUCENT`、`TOP|START` 和 `FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL | FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_NO_LIMITS`；`FLAG_LAYOUT_IN_SCREEN` 保证 x/y 以物理屏幕为坐标基准，不把状态栏下方误当作 y=0。
2. 服务启动时先创建面板 Window、应用网格和目录协调器，并启动目录与首屏图标的离屏预热；面板完整布局位于屏幕外 `x=1920`，根 View 保持可布局但 Window 与屏幕零相交且不可触摸。随后挂载触发窗，使真实竖条天然位于面板之上。关闭稳定态保留这份已准备状态，不销毁、不重新查询，也不参与屏内合成。
3. 方向锁定为打开手势后，只把既有面板 Window 切换到运动状态。运动阶段的透明容器固定在 `x=1290, y=90, 630 x 810`，右边缘精确到屏幕 `x=1920`；其中真正的软件内容固定宽 `600 px`，从 `translationX=610` 移动到 `0`。识别到横向手势时直接显示已准备页面的最右 `20 px`，随后从物理边缘向左进入，不允许重新 inflate、查询目录或先出现屏幕右缘空带。
4. 面板有且只有 `PARKED / MOVING / OPEN` 三种 Window 状态：关闭冻结态完整离屏、无屏内可见像素且不可触摸，但 View 保持可布局；拖动/停靠态在屏内、可见但 `FLAG_NOT_TOUCHABLE`；展开稳定态宽 `600 px`、可见且可触摸。每次状态切换只提交一次 WindowManager 布局更新，拖拽每帧不改变面板 Window 尺寸。
5. 触发窗位置为 `1870 - openDistancePx`：关闭端点精确为 `1870`，展开端点精确为 `1260`。面板内容使用相同 1:1 位移，因此把手左缘始终比面板已显示左缘内缩 `2 px`，不会跨在内容边界上。
6. 每个输入帧只更新内存位移、面板内容 `translationX` 和触发窗 x；WindowManager 的触发窗位置更新通过 Choreographer 合并为每帧最多一次，坐标未变化时不提交更新。
7. 面板 Window 与触发 Window 均不申请系统级窗口类型；`TYPE_APPLICATION_OVERLAY` 的系统排序负责让状态栏和高优先级安全窗口处于更高层，最终由用户在可安全触发的倒车影像/安全警告场景中验收。
8. 面板 Window 必须先于触发 Window 添加，因此真实触发窗在整个正常开合生命周期内天然位于面板之上。拖拽、停靠和回拉只更新触发窗 x，不得移除重加触发窗或绘制第二条镜像；这样展开触发区与面板重叠的 `x=1290..1320` 始终由同一真实触发窗接收手势，松手端点不会发生竖条刷新。
9. Android 无法把落在触发窗自身范围内的触摸继续分发给下层地图；`FLAG_NOT_TOUCH_MODAL` 只保证窗外触摸不被拦截。因此关闭态屏内 `x=1870..1920` 会由触发窗占用，地图验收必须测量其右侧按钮在该区域之外剩余的真实可点击面积，不能宣称触发区内可穿透。
10. 面板 Window 额外使用公开的 `FLAG_WATCH_OUTSIDE_TOUCH`。打开停靠完成后，必须把 Window 宽度从运动态 `630 px` 收回稳定态 `600 px`，此时软件内容覆盖 `x=1290..1890`，`x=1890..1920` 恢复为原车界面且不属于面板触摸区。仅在展开稳定态收到窗外首次按下 `ACTION_OUTSIDE` 时请求关闭；由于窗口保持 `FLAG_NOT_TOUCH_MODAL` 且没有透明全屏层，同一次原始点击继续交给下层车机界面。展开把手矩形 `x=1260..1320, y=90..900` 属于本软件交互区，不触发窗外关闭。
11. 把手外观来自目标车机原厂启动器的资源真值：浅色与深色资源均为 `30 x 810 px` 透明层，非透明包围盒为 `x=12..18, y=330..480`，主体 alpha 为 `43/255`；浅色使用黑色、深色使用白色。项目使用等价 XML shape 重建 `6 x 150 px`、`3 px` 圆角，不复制原车位图。
12. 深浅模式只读取 Android 标准 `Configuration.uiMode`，通过 `values` / `values-night` 切换。配置变化允许按新主题一次性重建面板与竖条，并保持面板当前开合距离；正常开合端点不得借主题刷新路径重建任何窗口。

### 6.3 全局返回边界

1. 只有关闭态触发条未形成有效拖拽的轻点才请求全局返回；有效左滑、纵向手势、取消事件和动画打断不得执行返回。
2. `GlobalBackActionGateway` 只保存当前 AccessibilityService 的进程内执行器；服务连接时注册、销毁时按对象身份注销，旧实例不得清除新实例。
3. AccessibilityService 的历史组件名 `com.tcrrry.desktop.debug.NavigationDemoAccessibilityService` 固定保留，使已启用用户覆盖安装后继续命中同一组件；实现与 Manifest 均属于 `main`，不能退回 Debug 专属源集。
4. 服务只调用一次公开 `GLOBAL_ACTION_BACK`；`onAccessibilityEvent` 不读取事件。XML 必须保持 `canRetrieveWindowContent=false`、`canRequestFilterKeyEvents=false`、`canPerformGestures=false`，不得创建 `TYPE_ACCESSIBILITY_OVERLAY` 或增加 HOME、RECENTS、媒体、自动点击能力。
5. 用户未启用服务、服务未连接或系统返回失败时，轻点不执行动作；触发条、左滑抽屉和其它应用管理能力继续可用，应用不自动打开无障碍设置页。

## 7. 手势状态流与阈值

1. `openDistancePx` 唯一范围为 `0..610`：`0=CLOSED`，`610=OPEN`；任何计算先 clamp 再渲染。
2. `ACTION_DOWN` 记录当前位移和稳定来源，不创建动画。移动超过系统 `scaledTouchSlop` 且水平距离不小于垂直距离的 `1.2` 倍时锁定水平手势；垂直优先则取消本轮开合并消费到本次输入结束。Android 不会把已经命中触发窗的同一事件序列重新投递给地图，禁止在实现或验收中承诺这种转交。
3. 关闭态只接受向左位移；展开态只接受向右回拉。锁定后面板位移与手指水平位移一比一，不使用速度加速、阻尼或橡皮筋效果。
4. 从展开态回拉：`closePullPx > 100` 时关闭；`closePullPx <= 100` 时恢复展开。恰好 `100 px` 不关闭。
5. 从关闭态打开：只有移动超过系统 `scaledTouchSlop` 且方向锁定为有效左滑后才进入打开手势；一旦进入，松手时只要 `openDistancePx >= 1` 就展开，不再要求超过半程。没有形成有效拖拽则保持关闭。
6. 动画被新手势打断、进程恢复遇到中间态或状态来源不明时，仍使用独立恢复中点：`openDistancePx >= 300` 展开，`< 300` 关闭；该阈值不得用于正常松手。
7. `ACTION_CANCEL` 返回本轮手势开始前的稳定态；服务重建或动画异常才使用第 6 条中点规则。
8. 停靠动画期间的新 `ACTION_DOWN` 先取消 Animator，再从当前位移继续；禁止跳回端点后重开动画。

## 8. 应用目录、主入口与排序

### 8.1 枚举规则

1. 在 `Dispatchers.IO` 使用 `ACTION_MAIN + CATEGORY_LAUNCHER` 调用 `queryIntentActivities`；不查询全部 package，不申请 `QUERY_ALL_PACKAGES`。
2. 排除 `ApplicationInfo.FLAG_SYSTEM` 或 `FLAG_UPDATED_SYSTEM_APP` 任一命中的包，以及 disabled 应用、disabled Activity 和无有效组件项。
3. 对 Android 标记为普通应用的原车融合项，只在 `OemIntegratedAppPolicy` 同时命中车型/固件、精确包名、官方签名 SHA-256 和车载专用组件时排除。当前唯一规则为 `S56_HQX` 原车融合微信；任一证据缺失时保留应用。禁止按安装时间、安装器、应用名称、开发者、包名前缀或 `/data/app` 路径猜测。
4. 按 `packageName` 分组，每包只保留一个入口：优先选择 `getLaunchIntentForPackage` 返回且存在于候选集的组件；否则按 `priority` 降序、`preferredOrder` 降序、完整组件名升序取第一项。
5. 显示名使用选中 `ResolveInfo.loadLabel`，空值回退 Application label，再回退包名；排序身份始终只用包名，不用本地化名称。
6. `AppEntry` 至少包含：`packageName`、扁平化 `componentName`、`label`、`firstInstallTime`、`lastUpdateTime`、`isSelf` 和 `iconKey`；领域模型不得持有 Drawable/Bitmap/Context。`canRequestUninstall` 由统一应用管理策略计算。
7. `isSelf` 只允许精确比较 `com.tcrrry.desktop`，目录合并时必须排除 `isSelf=true` 的条目，且不向其提供自卸载入口；不得按签名、开发者或 `com.tcrrry` 前缀过滤，确保 `03歌词` 走普通规则。
8. 增强文件管理器只允许精确比较 `org.fossify.filemanager.debug` 和公开 `MainActivity`；即使它移除了 `MAIN + LAUNCHER`，仍由仓库显式合成一个候选并参与普通排序、启动与卸载。不得按应用名称、签名或 `org.fossify` 前缀扩大识别范围。

### 8.2 持久化与合并

1. 使用私有 SharedPreferences 文件 `app_order_v1`，键 `ordered_apps_json`。
2. JSON 格式固定为 `{"schemaVersion":1,"entries":[{"packageName":"...","firstInstallTime":0}]}`，使用 Android `org.json` 解析，不手工拼接或拆字符串。
3. 合并算法：先按存储顺序保留“当前仍存在且 `firstInstallTime` 相同”的条目，再按本次 PackageManager 查询的稳定组件顺序追加其余条目。
4. 应用更新不改变 `firstInstallTime`，因此保持位置；卸载移除存储条目；卸载后重装的 `firstInstallTime` 改变，因此旧身份失效并追加末尾。
5. 损坏 JSON、重复包名或非法时间不崩溃：丢弃非法条目、记录不含个人数据的计数日志，并用当前查询结果重建一次。
6. 拖拽只改内存快照；普通松手仅当顺序改变时调用一次 `SharedPreferences.Editor.apply()`。包事件或冷启动合并发生变化时也只写一次。

### 8.3 包变化事件

1. Service 存活期动态监听 `PACKAGE_ADDED`、`PACKAGE_REMOVED`、`PACKAGE_REPLACED`、`PACKAGE_CHANGED`、`EXTERNAL_APPLICATIONS_AVAILABLE` 和 `EXTERNAL_APPLICATIONS_UNAVAILABLE`。
2. 事件只设置 dirty，不在 BroadcastReceiver 内查询包或加载图标；`500 ms` 静默窗口后合并刷新一次。
3. `EXTRA_REPLACING=true` 的移除/添加组合按更新处理；最终仍以 PackageManager 查询和 `firstInstallTime` 合并结果为真值。
4. 拖拽期间到达的事件延迟到拖拽结束；卸载系统页返回后，取消时无移除广播，成功时包移除广播负责删除图标。

## 9. 网格、拖拽和图标

1. 使用 `GridLayoutManager(4)`；面板左右各留 `18 px`，四列按可用宽度等分。页面顶部固定 `42 px` 留白与 `84 px` 居中标题，网格上下各留 `18 px`，这些值沿用原车应用中心已验证节奏。
2. 原车全屏应用中心的图标基准是 `108 x 108 px`；右侧小窗口按比例收敛为 `96 x 96 px`。应用 cell 布局高 `172 px`，ItemDecoration 上下各 `11 px`，最终行步长 `194 px`；名称距图标 `10 px`、`24 sp`、最多两行并末尾省略。顶部标题为 `38 sp` 加粗的“应用管理”。
3. “安装 APK”入口始终位于底部 `126 px` 动作区中的 `84 px` 次级动作，不参与 RecyclerView 或排序，也不依赖文件管理器；拖拽任一可卸载应用时，同一槽位互斥替换为卸载目标，安装与卸载不得同时可见或重叠。两个动作均不使用宽底板，只显示图标和文字。
4. 长按由 ItemTouchHelper 进入拖拽；成功进入后当前项在 `100 ms` 内视觉缩放到 `1.06` 倍，网格层临时提高 `24 px` 以保证拖动项高于安装/卸载动作；不增加底框或改变 cell 实际尺寸。`onMove` 只交换内存列表并让 RecyclerView 执行默认位移动画，不写磁盘。
5. 拖拽开始保存完整顺序快照；除 `03桌面` 自身外的可卸载应用（包括增强文件管理器）把底部动作区原位切换为 `84 px` 高卸载目标，拖动项中心点进入目标矩形即命中，离开即取消命中。命中时只增强卸载图标/文字颜色并缩放到 `1.06` 倍，不绘制整块危险色背景。
6. 普通松手：若顺序变化，写入一次；未变化不写。`ACTION_CANCEL`：恢复快照且不写。
7. 卸载松手：先恢复拖拽前快照且不写，再关闭抽屉并打开目标应用的系统“应用信息”页。用户在该系统页选择卸载后，系统继续展示原生确认；取消时原位置已恢复，成功时包移除广播完成删除和一次持久化。固定车机上禁止从悬浮服务直接发起 `ACTION_DELETE`，因为该固件会把可见确认框注册为错误的触摸区域。
8. 图标缓存键为 `packageName:lastUpdateTime:sizePx:densityDpi`，只保存资源 `drawer_app_icon_size` 当前定义的 `96 x 96` ARGB Bitmap，LRU 上限 `8 MiB`；应用更新删除该包旧键，`onTrimMemory` 按等级减半或清空。

## 10. 应用启动与系统动作

1. 点击应用、内置安装入口或卸载后由面板动作门禁拒绝重复请求并先关闭抽屉；只有关闭动画结束、Panel Window 已进入离屏 `PARKED` 状态后才能进入统一启动协调器。
2. 启动 Intent 使用查询时保存的组件与 `FLAG_ACTIVITY_NEW_TASK`；组件失效时只提示“应用暂时无法打开”，不退回隐式全包猜测。
3. 普通第三方目标 Activity 通过 Manifest metadata `com.tcrrry.icar.window.STANDARD_FLOATING_WINDOW=true` 自声明为标准浮窗；未声明时沿用直接启动，禁止按包名、签名或开发者维护名单决定普通应用的窗口类型。
4. 内置安装页、安装页中的增强 U 盘动作、卸载系统页及未来从抽屉打开的顶层设置页不依赖普通应用 metadata，必须调用协调器的强制互斥入口。隐式系统 Intent 在进入等待前通过 PackageManager 解析并固定为显式 ComponentName，防止 HOME 切换期间解析目标变化。
5. 需要互斥的顶层目标启动前只读 `Settings.Secure` 的 `com.mengbo.launcher3.settings.secure.window_mode`：实机确认 `0/1/2/3` 分别表示无占用、仅左侧 ADAS 卡片、仅标准浮窗、ADAS 与标准浮窗并存。`0/1` 不含标准浮窗，直接启动；`2/3` 先注册一次性 ContentObserver 与 `3000 ms` 超时，再启动 `ACTION_MAIN + CATEGORY_HOME + FLAG_ACTIVITY_NEW_TASK`；观察到 `0/1` 后注销并只启动目标一次。注册后发 HOME，HOME 返回后再单次读取一次用于收敛通知竞态，不使用 sleep 或轮询。
6. Secure 值缺失、读取失败、`0..3` 以外的值、HOME 失败、观察者/超时建立失败或等待超时均保守终止，注销全部句柄并提示用户先关闭当前窗口后重试；服务/面板释放也必须取消待启动请求。
7. 原生卸载使用 `ACTION_APPLICATION_DETAILS_SETTINGS` 与目标 `package:` URI 进入系统“应用信息”页，由该页继续进入系统卸载确认；该系统页作为抽屉顶层窗口强制互斥，不自行删除、不调用 shell、不监听私有安装器接口。
8. 增强文件管理器不依赖 Launcher 查询：应用目录显式使用契约中的 `MainActivity`，U 盘入口还必须读取该 Activity 的契约 metadata 且版本至少为 1。目标固件不会唤醒已停止的旧文件管理器浮窗任务，因此两个入口都固定使用 `NEW_TASK | CLEAR_TASK`，只清 Activity 任务、不清应用数据或权限，再创建确定的新窗口；包缺失、禁用、组件不可导出或契约不兼容时只隐藏 U 盘按钮，Service、触发条和内置 Download 安装继续运行。
9. 所有系统 Intent 先 `resolveActivity`；没有处理器时显示面向任务的短提示，Service 和触发条继续运行。

## 10.1 桌面表面占用租约

1. `DrawerWindowController` 继续独占抽屉开合状态，只输出一个“正在占用桌面表面”语义：有效横向手势成立或程序化展开启动时，在首个可见运动帧前置为 `true`；`MOVING`、`OPEN` 与收起动画期间保持；只有到达 `PARKED` 且 `openDistancePx=0` 后置为 `false`。

3. 绑定存续本身就是占用租约，不调用 Binder 业务方法，不发 OPEN/CLOSE 广播，也不使用轮询或心跳；完全收回、窗口失败、悬浮权限失效、Controller/Service 释放时幂等解绑全部提供方。
4. 配置重建只重建窗口，不改变占用语义；快速反向、动画取消和重复取得/释放不闪断租约。一个提供方发现、绑定、死亡或解绑异常不得阻断其他提供方或抽屉本身；没有任何提供方时抽屉保持原行为。
5. Manifest 仅通过 `<queries>` 声明该 Service Action 可见性，不新增权限；不得写 Secure Settings、硬编码歌词包名或向特定应用发送专用 Intent。

## 13. 开机、服务与恢复

1. `MainActivity` 使用 `Theme.NoDisplay`，只尝试调用 `startForegroundService` 并立即结束；不显示说明页、不主动检查后弹出 `SYSTEM_ALERT_WINDOW` 授权界面。

3. `BootReceiver` 只处理 `BOOT_COMPLETED` 和 `MY_PACKAGE_REPLACED`；仅当 `Settings.canDrawOverlays` 为真时启动服务，否则不后台弹权限页。
4. 服务重建默认恢复 CLOSED，离屏预热完整面板后再挂载触发窗；不持久化中间动画或 OPEN 状态，避免开机直接遮挡地图。
5. 权限被撤销、WindowManager 添加失败或 View 异常时立即释放所有本应用窗口并停止前台服务；不得影响其它应用触摸。
6. 不使用定时 Alarm、Job、WorkManager、忽略电池优化或高频自拉活。`START_STICKY + BOOT_COMPLETED + MY_PACKAGE_REPLACED` 是 V1 允许的恢复边界。
