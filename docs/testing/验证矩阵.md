# 验证矩阵

## 1. 当前入口

1. 项目初始化与 skill：`node scripts/check-project-ready.mjs && node scripts/check-skills.mjs`。
2. Android 配置与权限：`node scripts/check-android-config.mjs`。
3. 工具链：`./scripts/check-android-env.sh`；需要连接车机时追加 `--device`。
4. 单测、Lint 与构建：`./scripts/gradlew-jdk17.sh testDebugUnitTest lintDebug assembleDebug`。
5. 车机系统入口只读探测：`./scripts/check-device-capabilities.sh --package <普通第三方应用包名>`。
6. 文档/空白：`git diff --check`；未提交新仓库还需用源码扫描确认没有本机绝对路径或敏感材料。

## 2. 变更分级

| 变更类型 | 必须验证 |
|---|---|
| 只读查询 | 不默认跑构建；记录实际查询范围与是否改设备 |
| 普通文档 | 本轮相关文件 `git diff --check` |
| 项目总纲或验证入口 | `node scripts/check-project-ready.mjs` + 本轮相关文件 `git diff --check` |
| Skill | `node scripts/check-skills.mjs` + 本轮相关文件 `git diff --check` |
| 普通 Gradle、Manifest、资源、Kotlin 切片 | `assembleDebug`；命中已有直接相关单测时追加对应测试；产生可手测行为变化时自动覆盖安装 Debug APK 并检查启动 |
| 领域纯函数、排序、事件合并 | 直接相关边界单测 + `assembleDebug` |
| 悬浮窗口、手势、网格、拖拽 | `assembleDebug` + 自动覆盖安装与启动检查 + 交付具体用户手测路径 |
| 全局返回 AccessibilityService | `GlobalBackActionGatewayTest` + Android 配置检查 + `assembleDebug` + 用户手测轻点返回、左滑展开与服务未启用边界 |
| 应用枚举、启动、包广播 | 直接相关单测 + `assembleDebug` + 自动覆盖安装与启动检查 + 用户手测目录、启动和刷新 |
| 标准浮窗互斥、抽屉顶层窗口、跨应用占用租约 | 直接相关协调器单测 + `assembleDebug` + 自动覆盖安装与启动检查 + 用户手测应用/安装/卸载顶层窗口返回栈和歌词表面切换 |
| 内置 APK 安装与可选 U 盘增强 | `ApkScannerTest` + 文件管理器普通卸载资格 + Android 配置检查 + `assembleDebug` + 自动覆盖安装与启动检查 + 真机 Download 安装页、条件 U 盘按钮与系统安装器 |
| 增强文件管理器构建或升级 | 固定上游提交补丁 `git apply --check` + `coreDebug` 构建 + 包名/版本/签名检查 + 系统 Launcher 无入口 + `03桌面` 显式入口 + 关闭后重复启动 + 真实 U 盘根目录 |
| 原生卸载 | 资格单测 + `assembleDebug` + 自动覆盖安装与启动检查 + 默认使用可删除测试包手测取消/成功；用户在当前任务中明确指定普通第三方应用的精确包名并要求卸载时，确认数据影响并核对恢复 APK 后应执行真实卸载，不得以自动测试或调试阶段保护为由拒绝 |
| 开机/服务恢复 | `assembleDebug` + 自动覆盖安装与启动检查 + 用户在安全时机手测冷启动、服务恢复与车机重启 |
| 里程碑、提交/发布准备或明确要求完整验证 | Android 配置、全部单测、Lint、Debug 构建 + 本次范围内的真机验收清单 |
| 包名迁移、staging / production 签名 | 默认 Debug 构建；两类缺材料负向测试；双环境构建；APK 包名、单 signer、v2、证书摘要、秘密扫描与备份逐字节核对 |
| Release 版本管理 | `node scripts/bump-release-version.mjs --check`；Release APK 的 `versionName=1.0.0-icar03`、`versionCode` 与签名核对；Debug / Staging APK 版本保持 `defaultConfig` 基线 |
| 正式分发 | 人工门禁、离线双备份、版本递增、新包安装授权、同证书升级与回滚 |

## 3. 小切片交付闭环

1. 用户提出一个功能、调整或修复后，AI 只完成当前可独立运行的最小切片，不等待整个 V1 或历史依赖分组。
2. AI 默认执行第 2 节对应的基础机器检查。凡产生可在车机手测的应用行为变化，构建和直接相关测试通过后必须执行 `./scripts/install-debug-to-device.sh`，确认当前新包已覆盖安装且基础运行正常，再列出本轮最值得验证的具体操作路径。
3. 用户负责界面、视觉、手势、连续操作、系统弹窗和真实车辆场景的主要验收；反馈问题后，AI 定点修复并只重跑受影响的基础检查。
4. 本项目自身 Debug APK 的无清数据覆盖安装已获得长期授权，不需要逐轮询问。设备离线或基线不符时，AI 必须说明阻断且不得安装到其它设备；不得自动清数据、卸载应用、接受授权、重启车机或修改系统设置。
5. 完整单测、Lint、Debug 构建和真机验收清单只在里程碑收口、准备提交/发布、高风险系统能力变更或用户明确要求时执行，不因普通交付或正式收尾重复运行。
6. 用户可以在任一切片后要求继续、修复或提交；Debug 构建与安装都不代表发布。

## 4. 自动化用例基线

1. `DrawerGeometryTest`：运动容器右缘 `1920 px`、稳定内容右缘 `1890 px`、坐标端点、位移 clamp、正常打开 `0/1 px`、关闭 `100/101 px` 与异常恢复 `299/300 px` 阈值、真实把手位于内容内部、取消与异常归位，以及展开把手矩形边界。
2. `AppCatalogFilterTest` + `OemIntegratedAppPolicyTest`：launcher 资格、系统过滤、多入口选择、自身精确判断、`03歌词` 和增强文件管理器的普通卸载资格，以及原车融合微信的四项证据命中与误隐藏反例。
3. `AppOrderReconcilerTest`：更新保位、新装末尾、卸载移除、重装末尾、损坏/重复配置恢复。
4. `DragSessionTest`：内存换位、一次写入、零写入、取消恢复、卸载取消顺序、保护应用不进入卸载流程。
5. `PackageEventReducerTest`：`500 ms` 合并、替换语义、拖拽期间延迟刷新。
6. `StandardFloatingWindowLaunchCoordinatorTest`：普通目标直启，metadata 标准目标和强制顶层窗口在 `0/2/未知/读取失败` 状态下的直接启动、HOME 互斥、一次启动、重复点击、观察注册/取消、HOME/目标失败与 `3000 ms` 超时。
7. `SurfaceOccupancyLeaseCoordinatorTest`：触摸抖动不占用、有效运动开始占用、展开/收起/反向期间持续、PARKED 零位释放、服务释放幂等、无提供方和单提供方异常隔离。
8. `GlobalBackActionGatewayTest`：已连接执行器处理返回、注销后不可执行，以及旧服务实例注销不得清除当前新实例。
9. `ApkScannerTest`：Download 树广度优先扫描、大小写 APK 后缀、不可读目录隔离、URI 去重、修改时间降序和文件名稳定次序。
10. 修改领域规则、状态边界或已覆盖回归时，维护对应测试且不得弱化断言；纯界面、文案或资源切片不强制新增测试文件。

## 5. 用户真机验收菜单

以下条目用于相关切片的用户手测，以及里程碑或发布前的范围选择；普通切片不要求一次跑完全部条目。

1. 权限：启动 `03桌面` 时不自动跳授权页；悬浮权限已存在时服务恢复，权限不存在时不创建悬浮窗口。全局返回由用户在系统侧手动启用，应用不自动打开无障碍设置；Download 读取和 `REQUEST_INSTALL_PACKAGES` AppOp 由手机安装工具或 Debug 覆盖脚本前置授予，内置安装页没有“允许读取”按钮、不主动请求也不跳转未知来源设置。
2. 全局返回：抽屉关闭时轻点右侧触发条只返回一次；短滑未形成有效拖拽时按轻点处理，有效向左滑只展开抽屉且不返回；服务未启用或被系统停止时轻点无动作，但左滑抽屉继续可用。
3. 抽屉：关闭/展开坐标、拖拽首帧直接显示已准备页面并从屏幕右缘进入、页面和竖条在松手端点无刷新、竖条始终位于软件上层、最短有效左滑松手即自动展开、展开内容覆盖 `x=1290..1890` 且右侧保留 `30 px` 原车界面、`200 ms` 停靠、回拉阈值、手势打断和 `ACTION_CANCEL`。
4. 主题与布局：浅色把手为低透明黑色、深色把手为低透明白色；切换主题后常驻把手和已展开面板同步刷新。应用网格是首屏主体，顶部有明确间距，底部安装动作与拖拽卸载目标严格互斥且无宽底板。
5. 触摸：地图最右侧按钮保留足够点击区；展开态点击抽屉外原车控件时，同一次点击触发原车动作并使抽屉收起；触发条外透明区域不吞触摸。
6. 层级：状态栏、倒车影像和安全警告在抽屉之上；无法安全自动触发时保留最小人工验收。
7. 应用：枚举准确、每包一个入口、`03桌面` 自身不出现、已验证的原车融合微信不出现、`03歌词` 正常出现且具备普通卸载目标；增强文件管理器在系统 Launcher 查询中无入口，但在 `03桌面` 网格正常出现、启动并具备普通卸载目标。点击普通应用时先关闭抽屉，目标应用中触发条仍存在。
8. 标准浮窗：充电 ADAS 卡片单独展开、`window_mode=1` 时可直接打开内置安装页和增强文件管理器；已有标准浮窗或与 ADAS 并存、`window_mode=2/3` 时，分别执行“系统设置 -> 03桌面抽屉 -> 03歌词 / 安装 APK / 打开 U 盘 / 拖拽卸载系统页”，关闭新顶层窗口后最终回到桌面或保留强制 ADAS 卡片，旧设置不得回弹；反向从 03歌词打开系统设置时，歌词标准浮窗被系统收起。
9. 桌面占用：03歌词显示壁纸大区域时展开 03桌面，有效手势首帧起大区域退出、顶栏歌词保留；完全展开与收起动画期间不恢复，抽屉完全离屏后再按桌面状态和用户偏好恢复。触摸抖动不得触发切换。
10. 排序：长按成功后当前应用轻微放大，拖到底部时仍高于卸载动作，松手/取消恢复原尺寸与层级；普通应用和增强文件管理器的卸载命中都只放大并增强图标文字。同时验证实时让位、服务重建保持、更新保位、新装末尾、卸载移除、重装末尾。
11. 安装/卸载：Debug 覆盖安装后 Download 权限和未知来源 AppOp 均已授予，底部“安装 APK”始终进入内置页面且不出现页面内授权按钮或设置页；空态、扫描结果、点选 APK 和系统安装器顺序正确。增强文件管理器契约可用时页面显示“打开 U 盘”并直达根目录；返回桌面后重复进入仍必须创建可见窗口，不得只把休眠任务置前。缺失或不兼容时只隐藏该按钮。普通应用和文件管理器卸载继续由系统页面处理，取消恢复；失败不让触发条消失。
12. 恢复与稳定：关闭冻结态无目录轮询、动画和屏内合成；连续开关保留页面与滚动状态且不重复查询，包变化仍能更新；安装页停止后扫描取消并清空，开机、服务回收、应用升级、循环开关/拖拽/安装页与文件管理器启动无 Window 泄漏或后台扫描。
13. 性能：至少 40 个等价第三方入口，关闭态无轮询、无持续网格重绘和无屏内合成，打开、滚动、拖拽无明显连续掉帧。
