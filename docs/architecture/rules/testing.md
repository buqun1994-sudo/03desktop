# 验证规则

## 1. 默认规则

1. 代码或工程行为变更后，必须主动执行当前环境可完成的最低成本验证。
2. 编译、类型检查和 lint 只能证明基础正确，不等于用户可见闭环已验证。
3. UI、启动、导航、输入、文件读写、登录、支付、部署等行为变化，需要运行级 smoke 或客观阻断说明。
4. 不能为了让测试通过而降低断言强度。
5. 剩余人工验证必须压缩为最小闭环，禁止泛泛要求整体回归。
6. 项目启用多语言后，必须机械检查 locale JSON 可解析、key 集一致、值非空、源码引用 key 存在，以及新增用户可见文案未绕过多语言主链。

## 2. 03桌面项目规则

1. 触发条件：文档或工程底座变化。动作：运行项目就绪、skills、Android 配置、环境检查和 `git diff --check`。验证入口：`docs/testing/验证矩阵.md`。边界：不因纯 Git 收尾重跑无关业务 smoke。
2. 触发条件：代码、资源或 Manifest 变化。动作：运行 `testDebugUnitTest lintDebug assembleDebug`。验证：Gradle 全部任务成功。边界：编译成功不能替代窗口、输入和系统页面真机验证。
3. 触发条件：悬浮层、手势、启动、拖拽、安装、卸载、媒体或开机恢复变化。动作：在 `S56_HQX` 执行对应运行级 smoke，并保存不含敏感内容的结论。验证：行为、状态变化和可观测证据逐项记录。边界：模拟器只能辅助，不能替代固定固件与窗口层级。
4. 触发条件：设备验证会安装、卸载、清数据、授权、重启或改设置。动作：先确认目标和恢复方式，使用专门测试包。验证：执行前后包/设置状态对比。边界：禁止实际卸载 `03歌词`，只允许打开后取消其原生确认页。
5. 触发条件：完成一个敏捷施工阶段。动作：只运行本阶段相关自动化和必要构建，随后在已确认的 `S56_HQX` 上自动覆盖安装明确路径的 Debug APK，并执行能证明本阶段主路径的最短 smoke。验证：设备身份、安装结果、目标入口和无崩溃状态可观察。边界：不得清数据、卸载应用、自动授权、改系统设置或把 Debug 安装表述为发布。
6. 触发条件：最短 smoke 已覆盖本阶段主路径。动作：把视觉匹配、长时间连续操作、真实地图边缘触控、倒车影像/安全警告和主观媒体体验交给用户扩展验收。验证：记录用户反馈，问题回到同一阶段修复；用户确认后才提交。边界：AI 可自动发现的问题不得转交用户代测，最终 V1 发布门禁仍以完整验证矩阵为准。
