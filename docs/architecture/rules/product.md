# 产品规则

## 1. 默认规则

1. 需求必须落到目标用户、核心路径和完成标准。
2. 不确定的商业判断、定价、权限、隐私承诺和对外承诺必须人工确认。
3. V1 不做范围要明确记录，避免 AI 把未来能力提前塞入项目。
4. 产品目标或长期边界变化时，只同步受影响的需求、架构或验证真值；普通功能切片不强制更新收尾记录。

## 2. 03桌面项目规则

1. 触发条件：增加应用管理能力。动作：只服务第三方可启动应用的发现、启动、排序、原生安装/卸载。验证：与产品基线逐条比对。边界：不扩张为应用商店、权限管理器、任务管理器或车辆控制器。
2. 触发条件：判断 `03歌词`。动作：始终按普通第三方应用处理，允许显示、排序和原生卸载确认。验证：过滤和卸载资格单测显式包含 `com.ninepointnine.desktoplyrics`。边界：不得按开发者、签名或包名前缀提供保护。
3. 触发条件：处理 `03桌面` 自身。动作：按决策 0002 仅以精确包名 `com.ninepointnine.desktop` 从自身网格隐藏，并且不从自身面板提供自卸载入口。验证：自身过滤、卸载资格和 `03歌词` 普通资格单测同时通过。边界：不得按签名、开发者或包名前缀扩大过滤，也不得阻止系统设置、原厂应用管理或其它标准入口卸载 `03桌面`。
4. 触发条件：处理车机增强文件管理器。动作：只以精确包名和公开 `MainActivity` 显式合成到 `03桌面` 网格，按普通应用显示、排序、启动和卸载；增强版自身移除系统 Launcher 入口。底部“安装 APK”固定打开内置页面，文件管理器只为页面提供条件 U 盘入口。验证：目录候选、普通卸载资格、系统 Launcher 无入口和真机 U 盘直达。边界：文件管理器不得成为 Download 安装前置依赖，也不得按名称、签名或包名前缀扩大识别。
5. 触发条件：普通应用区内存在原车融合应用。动作：只对已完成实车取证的项目建立排除规则，且车型/固件、精确包名、官方签名和车载专用组件必须全部命中。当前唯一项为 `S56_HQX` 上的原车融合微信。验证：正向用例隐藏完整命中的原车微信，反向用例保留其它车型、手机版微信、改签微信和其它腾讯应用。边界：不根据安装时间、安装器、应用名称、开发者、包名前缀或 `/data/app` 路径猜测预装身份。
6. 触发条件：评估媒体控制。动作：目标固件上的全局媒体键不能可靠控制当前会话，V1 移除媒体入口；只有通知使用权、安全边界、真实 MediaSession 控制与完整媒体卡片另行形成方案并获确认后才可重新进入范围。验证：抽屉不再出现无效媒体按钮，权限白名单不新增通知监听。边界：不得用车厂私有广播、无障碍、shell 或孤立的装饰按钮伪装媒体能力。
7. 触发条件：从抽屉启动任一顶层窗口。动作：普通第三方应用只依据目标 Activity 的通用 metadata 判断；内置安装页、增强 U 盘动作、系统应用详情卸载页及未来新增的顶层设置页强制加入全局互斥。车机 `window_mode=0/1/2/3` 分别表示无占用、仅左侧 ADAS 卡片、仅标准浮窗、ADAS 与标准浮窗并存；`0/1` 直接启动，`2/3` 注册一次性观察并先退 HOME，观察到 `0/1` 后只启动目标一次，关闭目标后回到桌面而不是重新露出旧标准窗口。验证：四态直启/互斥、重复点击、失败、取消与超时测试，并在车机分别从充电 ADAS 卡片和已占用标准浮窗打开安装页、文件管理器、卸载页确认返回栈。边界：其它值或读取失败保守终止；除已确认文件管理器契约外不维护第三方包名列表，不写 Secure，不枚举或停止任务。
8. 触发条件：第三方应用需要感知抽屉占用桌面。动作：只通过协议版本 1 的 exported bound service 绑定生命周期表达占用，完全收回后解绑。验证：有效手势、完整收起、快速反向、释放与无提供方测试。边界：不发一次性广播、不轮询、不调用 Binder 业务方法、不向特定产品发专用 Intent。
9. 触发条件：处理右侧触发条轻点。动作：关闭态未形成有效拖拽时执行一次系统全局返回；向左滑动仍只打开抽屉。验证：网关单测和真机分别验证轻点、短滑、有效左滑、服务未启用。边界：不增加 HOME、RECENTS、媒体或自动点击，不读取无障碍事件和窗口内容。
