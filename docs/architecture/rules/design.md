# 设计规则

## 1. 默认规则

1. 设计应服务目标用户和核心任务，不用装饰替代信息架构。
2. 页面、组件、状态和交互应形成稳定系统，不为单次页面复制孤立样式。
3. UI 文案应表达用户可感知结果，不解释内部实现。
4. 响应式、可访问性、空态、加载态、错误态和权限不足态应进入验收。
5. 多语言界面必须按当前界面语言显示语言名称和用户任务，不向最终用户暴露 locale code；最长翻译、换行、按钮稳定尺寸和 RTL 适用性必须进入视觉验收。

## 2. 03桌面项目规则

1. 触发条件：修改抽屉 UI。动作：以 `S56_HQX` 的 `1920 x 1080` 深色车机界面为唯一画布，保持四列、固定触控区和克制动效。验证：真机截图、坐标测量和长名称测试。边界：V1 不做手机/平板响应式，也不增加搜索、收藏或说明型面板。
2. 触发条件：修改把手或悬浮入口。动作：使用低不透明度 `6 x 150 px` 细竖线，不使用文字按钮、圆形悬浮按钮或装饰卡片。验证：关闭/展开端点截图与地图边缘点击 smoke。边界：可见把手不能扩大实际触摸窗或遮挡系统安全界面。
3. 触发条件：应用名称或状态文案变化。动作：名称最多两行、末尾省略，不动态缩小字体；状态只说明任务、结果和下一步。验证：最长名称、空态、权限拒绝和失败提示截图。边界：不向用户显示包名、Intent、权限常量或调试信息。
4. 触发条件：拖拽交互变化。动作：RecyclerView 项实时让位，卸载目标明确但不夸张，取消必须恢复原有效位置。验证：连续拖拽录屏与取消卸载 smoke。边界：拖拽动画不能改变 cell 固定尺寸或底部快捷区整体布局。
