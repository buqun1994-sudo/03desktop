# AI 协作规则

## 1. 默认规则

1. AI 必须先读取根 `AGENTS.md` 和命中任务的路由文档。
2. 低风险缺字段任务可以合理假设并推进，高风险任务缺范围、完成标准或人工门禁时必须追问。
3. 发现同类问题第二次出现时，不只修当前问题，还要沉淀规则、测试、skill 或 hook。
4. 收尾必须说明实际验证和剩余最小人工确认。
5. 不把一次会话的临时判断提升为长期架构结论。
6. 发现适合所有新项目默认具备的能力、skill、规则、检查或文档槽位时，必须记录为候选通用能力；确认跨项目通用后通过 `template-feedback` 回流到本地模板源 `/Users/q/Documents/Projects/NewProject`，不能让复制后的项目把自己当作模板源。
7. 当前工作区无法访问本地模板源时，交付说明必须标记“待回流本地模板源”，并写清候选内容、证据、去专有化要求和建议落点。
8. 创建或更新项目级 skill 时必须使用 `skill-authoring`，并同步能力池、验证矩阵和进度记录。

## 2. 03桌面敏捷协作节奏

1. 触发条件：进入 V1 代码、资源或 Manifest 施工。动作：先读取已确认的 V1 方案，把任务切成可独立运行和验收的最小阶段，在既有分层内解决根因，不保留临时旁路、重复真值或仅为演示存在的代码。验证：每阶段的物理文件、状态流和对应测试都能从方案追溯。边界：快速推进不等于跳过架构边界，也不提前施工后续阶段。
2. 触发条件：本阶段代码完成。动作：运行与改动直接相关的自动检查、测试和 Debug 构建；车机在线时自动覆盖安装，并对本阶段主路径执行最短真机 smoke。验证：构建、安装、启动或目标状态均有可观测结果。边界：文档、只读查询和纯 Git 收尾不重复安装，也不重跑无关全量回归。
3. 触发条件：AI 的最短闭环通过。动作：交付当前车机版本给用户做更广的视觉、连续操作和真实车辆场景体验，不默认提交。验证：用户明确反馈问题或确认无问题。边界：用户体验验收不能替代 AI 在当前环境可完成的编译、相关测试、安装和主路径 smoke。
4. 触发条件：用户反馈问题。动作：继续定位根因、定点修复、重新构建安装并重复本阶段最短闭环。验证：反馈现象消失且未破坏本阶段不变量。边界：不得为赶进度叠加临时特判。
5. 触发条件：用户确认无问题、明确要求提交，或任务开始时已经明确授权完成后提交。动作：使用 `task-closeout` 复用有效验证、更新进度并只提交授权范围。验证：交付中提供提交哈希和未推送/未发布状态。边界：不得把一次提交授权外推到后续施工阶段。

这套节奏是 `03桌面` 当前设备、用户验收方式和开发阶段的项目事实，不作为 `NewProject` 的跨项目默认规则回流。
