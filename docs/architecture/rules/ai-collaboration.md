# AI 协作规则

## 1. 默认规则

1. AI 必须先读取根 `AGENTS.md` 和命中任务的路由文档。
2. 低风险缺字段任务可以合理假设并推进，高风险任务缺范围、完成标准或人工门禁时必须追问。
3. 发现同类问题第二次出现或用户明确纠偏时，再评估沉淀规则、测试、skill 或 hook；普通功能施工不触发沉淀流程。
4. 普通交付说明实际机器检查和交给用户体验的具体行为；只有正式收尾才输出完整交接状态。
5. 不把一次会话的临时判断提升为长期架构结论。
6. 发现适合所有新项目默认具备的能力、skill、规则、检查或文档槽位时，必须记录为候选通用能力；确认跨项目通用后通过 `template-feedback` 回流到本地模板源 `/Users/q/Documents/Projects/NewProject`，不能让复制后的项目把自己当作模板源。
7. 当前工作区无法访问本地模板源时，交付说明必须标记“待回流本地模板源”，并写清候选内容、证据、去专有化要求和建议落点。
8. 创建或更新项目级 skill 时必须使用 `skill-authoring`，并同步能力池、验证矩阵和进度记录。

## 2. 03桌面敏捷协作节奏

1. 触发条件：用户要求实现、调整或修复普通功能。动作：直接定位并实现一个可独立运行的最小切片，不强制先输出方案或等待“开始施工”。验证：完成 `AGENTS.md` 规定的基础机器检查；若产生可手测的应用行为变化，再自动覆盖安装当前 Debug APK 并确认基础运行状态后交付。边界：安全红线、除本项目 Debug 覆盖安装外的破坏性设备操作、正式发布和会产生显著不同结果的范围歧义仍须先确认。
2. 触发条件：当前请求只覆盖 V1 的一部分。动作：只完成当前切片并交给用户体验，不等待其余 V1 能力，也不把历史 3 个检查点当作交付门禁。验证：当前切片能够构建，且当前 Debug APK 已自动覆盖安装并可启动。边界：纯文档、只读查询、纯测试和纯 Git 操作不安装；继续遵守 V1 方案中的架构、权限和系统接口边界。
3. 触发条件：功能具有界面、窗口、手势、系统页面或车机场景效果。动作：自动把新包安装到目标车机，再把交互和体验判断明确交给用户；AI 不为替代用户点击而扩写自动化、反复操作设备或延迟交付。验证：AI 先确认包已安装且基础运行正常，用户再按交付列出的具体路径体验并反馈。边界：AI 必须修复机器检查已经发现的错误，不能把旧包、编译失败或立即崩溃交给用户发现。
4. 触发条件：用户反馈问题。动作：围绕反馈现象定位根因、定点修复，只重跑受影响的基础检查后再次交付。验证：机器侧无新增基础错误，行为结果由用户复验。边界：不叠加临时特判，不默认扩大成全量回归。
5. 触发条件：用户明确要求完整验证、准备提交/发布、里程碑收口或高风险系统能力变更。动作：再升级到完整自动测试、Lint、构建和适用的真机 smoke。验证：按 `docs/testing/验证矩阵.md` 的里程碑级口径记录。边界：该升级不反向适用于普通功能切片。
6. 触发条件：用户明确要求提交、交接、handoff、归档或正式收尾。动作：使用 `task-closeout` 复用已有结果并只处理授权范围。验证：提供对应的提交或交接状态。边界：普通功能交付、状态汇报和用户开始手测不触发正式收尾。

这套用户主验收节奏是 `03桌面` 当前设备、用户协作偏好和开发阶段的项目事实，不作为 `NewProject` 的跨项目默认规则回流。
