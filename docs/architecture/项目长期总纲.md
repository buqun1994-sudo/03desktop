# 项目长期总纲

## 1. 文档定位

1. 本文是 `03桌面` 的系统级真值；具体物理文件、算法阈值和测试用例见 `docs/plans/V1架构施工方案.md`。
2. 项目类型：`desktop-client`，具体形态为 Android 9 原生车机客户端，不是 PC 桌面客户端，也不替换 Android HOME。
3. 一句话定位：Android 9 车机上补齐第三方应用展示与管理能力的轻量右侧应用抽屉。
4. 当前阶段：V1 业务代码已完成，进入用户主导的体验与小切片修复；视觉、尺寸、间距、颜色和交互按用户反馈逐项迭代。

## 2. 平台与产品身份

1. 唯一目标设备：`S56_HQX`，Android 9 / SDK 28，`1920 x 1080`，高通 8155，整机负载偏高。
2. 工程技术栈：Kotlin `1.9.22`、XML Views、Android Gradle Plugin `8.2.2`、Gradle `8.2`、Java 17。
3. SDK 策略：`compileSdk=34` 使用现有工具链；`minSdk=28`、`targetSdk=28` 对齐唯一交付系统。扩大系统范围前必须单独升级并验证现代权限、存储和前台服务规则。
4. 应用身份：`applicationId` 与 `namespace` 均为 `com.ninepointnine.desktop`；版本从 `versionCode=1`、`versionName=0.1.0` 起步。
5. 发布身份：staging 与 production 各使用一套 `03桌面` 独立 RSA 4096 证书；签名材料在仓库外管理，后续升级必须保持相同 `applicationId` 与对应环境证书，`versionCode` 单调递增。
6. `03歌词` 的身份为 `com.ninepointnine.desktoplyrics`；它只是一款普通第三方应用，不允许依赖、源码共享或特殊保护。

## 3. 架构分层与依赖方向

1. 界面呈现层：无界面启动 Activity、悬浮窗口 View 和网格适配器，只渲染状态并转发用户意图。
2. 应用流程层：抽屉协调器、应用目录协调器、拖拽协调器、内置 APK 安装、可选 U 盘增强和卸载流程，负责用例编排与异步时序。
3. 领域模型层：应用条目、应用管理策略、抽屉状态、排序状态、拖拽会话和用户可见错误，不依赖 Android UI 类型。
4. 适配器层：PackageManager、WindowManager、SharedPreferences、系统 Intent、系统广播与单动作全局返回 AccessibilityService 的唯一入口。
5. 基础设施层：轻量前台服务、开机接收器、图标内存缓存和应用顺序持久化。
6. 依赖只能从界面/应用流程指向领域端口，再由适配器实现；不得在 View、Adapter、BroadcastReceiver 或 Service 中复制应用过滤、排序或资格规则。

## 4. 核心主链

1. 进程恢复主链：`BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` -> 启动前台服务 -> 在屏幕外预热面板内容并创建右侧触发窗口 -> 用户手势时只移动既有面板，不重新查询目录。
2. 抽屉主链：触发窗口手势 -> 领域状态机计算位移与停靠目标 -> WindowManager 更新单一面板容器 -> 展开；窗外首次按下 -> 收起面板，同时由非模态窗口让原始点击继续到达下层界面。
3. 全局返回主链：关闭态轻点触发条 -> 进程内网关调用已连接的 AccessibilityService -> 只执行一次公开 `GLOBAL_ACTION_BACK`；滑动手势、服务未连接和执行失败均不得转化为其它系统动作。
4. 应用目录主链：PackageManager 查询 launcher activity -> 系统应用与已验证原车融合应用过滤 -> 每包选定主入口 -> 合并持久顺序 -> UI 快照。
5. 启动主链：点击任一顶层动作 -> 先执行抽屉关闭动画 -> 关闭完成回调 -> 普通应用按 metadata，内置安装页、增强文件管理器和卸载系统页按强制规则进入统一互斥协调器 -> 必要时先 HOME 并等待旧标准浮窗退场 -> 启动已固定的显式目标 -> 失败时显示简短提示。
6. 排序主链：长按开始拖拽 -> 内存列表实时移动 -> 松手一次写入包名顺序；拖入卸载区时等待系统结果，取消恢复拖拽前快照。
7. 包变化主链：安装/替换/卸载广播 -> 去抖后重新查询目录 -> 更新/新增/删除语义合并 -> 提交 UI 快照；禁止轮询。
8. APK 主链：手机安装工具或 Debug 覆盖脚本在安装时授予 Download 读取权限和 `REQUEST_INSTALL_PACKAGES` AppOp -> 用户点击底部“安装 APK” -> `03桌面` 关闭抽屉并打开内置安装页 -> 直接按修改时间扫描 APK -> 用户点选 -> 通过 FileProvider 只读 URI 直接交给系统安装器；扫描只在页面可见期间存在。任一前置授权缺失时只报告安装流程故障，不从页面跳转授权。
9. U 盘增强主链：安装页检测精确文件管理器组件的契约 metadata -> 契约版本至少为 1 时显示“打开 U 盘” -> 清理该应用在车机休眠浮窗栈中的旧任务后，通过显式动作启动增强版 -> 增强版自行解析当前已挂载的可移动卷并打开根目录；缺失或不兼容时按钮不出现，Download 安装不受影响。
9. 媒体能力不进入 V1：目标固件不可靠响应普通应用分发的全局媒体键；完整会话控制所需通知使用权不在权限白名单中，不展示伪媒体入口，也不接车厂私有旁路。

## 5. 长期不变量

1. 正式运行不依赖手机、电脑、ADB、网络或 root；全局返回依赖用户手动启用本应用的 AccessibilityService，但抽屉其余功能不依赖该服务。
2. 抽屉关闭时只保留轻量触发窗口；应用网格不存在于 WindowManager，不扫描包、不加载图标、不持续动画。
3. `03桌面` 只读取 Download 中用于用户点选的 APK 元数据，不删除 APK；系统安装器和卸载器拥有最终判断权，本应用不静默操作、不伪造结果。
4. 应用排序唯一真值是包名列表；更新保持位置，新包追加，卸载移除，卸载后重装按新包处理。
5. 图标只缓存缩放后的位图，缓存为有上限的内存 LRU；不持久化原始 Drawable，不持有 Activity Context。
6. `03桌面` 只按精确包名 `com.ninepointnine.desktop` 从自身网格隐藏，并且不从自身面板发起自卸载；车机增强版文件管理器按精确组件显式合成到目录中，但显示、排序和卸载资格均走普通第三方应用规则。`03歌词` 同样永远走普通第三方应用规则。原车融合应用只能在车型/固件、精确包名、官方签名和车载专用组件全部通过实车验证后排除，不猜测预装身份。
7. 悬浮层必须高于地图和普通第三方应用，低于状态栏、倒车影像和车辆安全警告；实机观察与系统默认窗口优先级不一致时，停止施工并定位窗口类型，不通过扩大权限强行覆盖。
8. 任何第三方应用、文件管理器入口或系统 Intent 失败都只能影响当前操作，不得导致触发条消失或地图/原厂桌面失去交互；禁止用透明全屏窗口实现窗外点击收起。
9. 从抽屉打开的顶层窗口必须共享一个标准浮窗互斥入口；关闭新窗口后不得重新露出启动前的系统设置、行车记录仪、账号或应用中心。需要返回结果的授权或安装子页面保持当前任务内的正常父子关系。
10. 全局返回服务只允许 `GLOBAL_ACTION_BACK`，必须关闭窗口内容读取、按键过滤和手势能力；历史组件名为升级兼容锚点，不得无迁移方案改名导致现有授权失效。

## 6. 权限与安全边界

1. V1 的 `<uses-permission>` 只允许：`SYSTEM_ALERT_WINDOW`、`FOREGROUND_SERVICE` 和 `RECEIVE_BOOT_COMPLETED`。卸载经由系统“应用信息”页进入原生确认，不申请存储、安装或删除权限。
2. 悬浮权限需在系统侧完成；`03桌面` 启动时不检查后主动弹授权页。权限不存在时服务自行停止，不建立悬浮窗口。
3. 全局返回 AccessibilityService 由用户在系统侧手动启用，不自动弹授权页；服务不读取事件或窗口内容，只执行一次公开系统返回。
4. 禁止申请：`QUERY_ALL_PACKAGES`、`MANAGE_EXTERNAL_STORAGE`、安装/卸载系统特权、通知监听、root、忽略电池优化、录屏、位置、联系人、麦克风、相机及车辆控制权限；禁止扩展全局返回服务的能力边界。
5. V1 不声明 `INTERNET`；未来若出现联网需求，必须作为新需求重新审查数据、安全和性能边界。
6. `03桌面` 只声明 Android 9 Download 安装所需的 `READ_EXTERNAL_STORAGE`、`REQUEST_INSTALL_PACKAGES` 和 FileProvider，不申请全文件管理、不持有 SAF 授权、不读取 U 盘；独立文件管理器的权限与数据不并入 `03桌面`。

## 7. 性能预算

1. 手势帧只计算水平位移、速度和窗口位置；不得在 `ACTION_MOVE` 查询包、读磁盘、解码图标或触发完整列表 diff。
2. 停靠动画固定 `200 ms`；不使用动态模糊、实时采样、持续截图或高频背景动画。
3. 服务建立时离屏加载一次应用目录与首屏图标，此后只由包变化事件触发目录刷新；图标尺寸固定，LRU 默认上限 `8 MiB`，超限逐出并响应系统内存回收通知。
4. 排序仅在拖拽松手后写一次 SharedPreferences；包变化广播合并窗口 `500 ms`，一次安装流程的多条广播只刷新一次。
5. “安装 APK”入口始终打开内置页面；页面不请求 Download 权限，扫描协程只在页面可见且安装流程已正确授权时运行，页面停止后立即取消并清空列表，不使用文件观察器或后台索引。权限意外缺失时只显示安装授权故障，不维护第二套授权入口。

## 8. 验证入口

1. 日常切片构建：`./scripts/gradlew-jdk17.sh assembleDebug`；命中已有直接相关单测时追加对应测试。
2. 规则或入口变化：按 `docs/testing/验证矩阵.md` 选择 `check-project-ready`、`check-skills`、Android 配置或相关文件 `git diff --check`，不默认全部执行。
3. 完整机器检查：`./scripts/gradlew-jdk17.sh testDebugUnitTest lintDebug assembleDebug`，只在里程碑、提交/发布准备、高风险变更或用户明确要求时执行。
4. 车机能力只读检查：`./scripts/check-device-capabilities.sh --package <普通第三方应用包名>`，仅在相关能力调查时使用且不改变设备。
5. 运行级效果由用户按 `docs/testing/验证矩阵.md` 手动体验；凡代码、资源、Manifest 或 Gradle 改动产生可手测行为，基础检查通过后由 AI 自动覆盖安装当前 Debug APK 并确认应用、进程和悬浮服务可启动。
