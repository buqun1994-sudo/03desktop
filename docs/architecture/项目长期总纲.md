# 项目长期总纲

## 1. 文档定位

1. 本文是 `03桌面` 的系统级真值；具体物理文件、算法阈值和测试用例见 `docs/plans/V1架构施工方案.md`。
2. 项目类型：`desktop-client`，具体形态为 Android 9 原生车机客户端，不是 PC 桌面客户端，也不替换 Android HOME。
3. 一句话定位：Android 9 车机上补齐第三方应用展示与管理能力的轻量右侧应用抽屉。
4. 当前阶段：V1 业务代码已完成，进入用户主导的体验与小切片修复；视觉、尺寸、间距、颜色和交互按用户反馈逐项迭代。

## 2. 平台与产品身份

1. 唯一目标设备：`S56_HQX`，Android 9 / SDK 28，`1920 x 1080`，高通 8155，整机负载偏高。
2. 工程技术栈：Kotlin `1.9.22`、XML Views、Android Gradle Plugin `8.2.2`、Gradle `8.2`、Java 17。
3. SDK 策略：`compileSdk=34` 使用现有工具链；`minSdk=28`、`targetSdk=28` 对齐唯一交付系统。扩大系统范围前必须单独升级并验证现代权限、存储和前台服务规则。
4. 应用身份：`applicationId` 与 `namespace` 均为 `com.tcrrry.desktop`；版本从 `versionCode=1`、`versionName=0.1.0` 起步。
5. 发布身份：创建 `03桌面` 独立 release keystore，在仓库外至少双份备份；后续升级必须保持相同 `applicationId` 与签名证书，`versionCode` 单调递增。
6. `03歌词` 的身份为 `com.tcrrry.desktoplyrics`；它只是一款普通第三方应用，不允许依赖、源码共享或特殊保护。

## 3. 架构分层与依赖方向

1. 界面呈现层：Activity、悬浮窗口 View、网格适配器和安装页面，只渲染状态并转发用户意图。
2. 应用流程层：抽屉协调器、应用目录协调器、拖拽协调器和安装/卸载流程，负责用例编排与异步时序。
3. 领域模型层：应用条目、抽屉状态、排序状态、拖拽会话、APK 文件条目和用户可见错误，不依赖 Android UI 类型。
4. 适配器层：PackageManager、WindowManager、SharedPreferences、StorageVolume、系统 Intent 与系统广播的唯一入口。
5. 基础设施层：轻量前台服务、开机接收器、图标内存缓存和应用顺序持久化。
6. 依赖只能从界面/应用流程指向领域端口，再由适配器实现；不得在 View、Adapter、BroadcastReceiver 或 Service 中复制应用过滤、排序或资格规则。

## 4. 核心主链

1. 进程恢复主链：`BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` -> 启动前台服务 -> 仅创建右侧触发窗口 -> 用户手势时才创建面板内容。
2. 抽屉主链：触发窗口手势 -> 领域状态机计算位移与停靠目标 -> WindowManager 更新单一面板容器 -> 展开；窗外首次按下 -> 收起面板，同时由非模态窗口让原始点击继续到达下层界面。
3. 应用目录主链：PackageManager 查询 launcher activity -> 系统应用与已验证原车融合应用过滤 -> 每包选定主入口 -> 合并持久顺序 -> UI 快照。
4. 启动主链：点击任一顶层动作 -> 先执行抽屉关闭动画 -> 关闭完成回调 -> 普通应用按 metadata、安装/卸载等顶层窗口按强制规则进入统一互斥协调器 -> 必要时先 HOME 并等待旧标准浮窗退场 -> 启动已固定的显式目标 -> 失败时显示简短提示。
5. 排序主链：长按开始拖拽 -> 内存列表实时移动 -> 松手一次写入包名顺序；拖入卸载区时等待系统结果，取消恢复拖拽前快照。
6. 包变化主链：安装/替换/卸载广播 -> 去抖后重新查询目录 -> 更新/新增/删除语义合并 -> 提交 UI 快照；禁止轮询。
7. APK 主链：用户进入安装页 -> 当次扫描下载目录与已挂载公共卷 -> 展示 `.apk` -> 校验未知来源授权 -> 交由系统安装器。
8. 媒体能力不进入 V1：目标固件不可靠响应普通应用分发的全局媒体键；完整会话控制所需通知使用权不在权限白名单中，不展示伪媒体入口，也不接车厂私有旁路。

## 5. 长期不变量

1. 正式运行不依赖手机、电脑、ADB、网络、root 或无障碍服务。
2. 抽屉关闭时只保留轻量触发窗口；应用网格不存在于 WindowManager，不扫描包、不加载图标、不持续动画。
3. 系统安装器和卸载器拥有最终判断权；本应用不删除 APK、不静默操作、不伪造结果。
4. 应用排序唯一真值是包名列表；更新保持位置，新包追加，卸载移除，卸载后重装按新包处理。
5. 图标只缓存缩放后的位图，缓存为有上限的内存 LRU；不持久化原始 Drawable，不持有 Activity Context。
6. `03桌面` 只按精确包名 `com.tcrrry.desktop` 从自身网格隐藏，并且不从自身面板发起自卸载；系统标准入口仍可卸载。`03歌词` 永远走普通第三方应用规则。原车融合应用只能在车型/固件、精确包名、官方签名和车载专用组件全部通过实车验证后排除，不猜测预装身份。
7. 悬浮层必须高于地图和普通第三方应用，低于状态栏、倒车影像和车辆安全警告；实机观察与系统默认窗口优先级不一致时，停止施工并定位窗口类型，不通过扩大权限强行覆盖。
8. 任何第三方应用、APK 文件或系统 Intent 失败都只能影响当前操作，不得导致触发条消失或地图/原厂桌面失去交互；禁止用透明全屏窗口实现窗外点击收起。
9. 从抽屉打开的顶层窗口必须共享一个标准浮窗互斥入口；关闭新窗口后不得重新露出启动前的系统设置、行车记录仪、账号或应用中心。需要返回结果的授权或安装子页面保持当前任务内的正常父子关系。

## 6. 权限与安全边界

1. V1 允许申请：`SYSTEM_ALERT_WINDOW`、`FOREGROUND_SERVICE`、`RECEIVE_BOOT_COMPLETED`、`REQUEST_INSTALL_PACKAGES` 和 `READ_EXTERNAL_STORAGE`（仅 Android 9 APK 扫描）。卸载经由系统“应用信息”页进入原生确认，不申请 `REQUEST_DELETE_PACKAGES`。
2. 悬浮窗与未知来源安装属于用户逐项授权；拒绝时保留可返回的设置入口和任务化说明，不反复弹窗。
3. 禁止申请：`QUERY_ALL_PACKAGES`、`MANAGE_EXTERNAL_STORAGE`、安装/卸载系统特权、通知监听、无障碍、root、忽略电池优化、录屏、位置、联系人、麦克风、相机及车辆控制权限。
4. V1 不声明 `INTERNET`；未来若出现联网需求，必须作为新需求重新审查数据、安全和性能边界。
5. APK 扫描只发生在用户主动进入页面后；只读取文件元数据与系统解析信息，不上传路径、包信息或设备信息。

## 7. 性能预算

1. 手势帧只计算水平位移、速度和窗口位置；不得在 `ACTION_MOVE` 查询包、读磁盘、解码图标或触发完整列表 diff。
2. 停靠动画固定 `200 ms`；不使用动态模糊、实时采样、持续截图或高频背景动画。
3. 服务建立时离屏加载一次应用目录与首屏图标，此后只由包变化事件触发目录刷新；图标尺寸固定，LRU 默认上限 `8 MiB`，超限逐出并响应系统内存回收通知。
4. 排序仅在拖拽松手后写一次 SharedPreferences；包变化广播合并窗口 `500 ms`，一次安装流程的多条广播只刷新一次。
5. APK 扫描在后台线程执行，可取消；离开页面立即丢弃结果，不建立文件观察器和后台索引。

## 8. 验证入口

1. 日常切片构建：`./scripts/gradlew-jdk17.sh assembleDebug`；命中已有直接相关单测时追加对应测试。
2. 规则或入口变化：按 `docs/testing/验证矩阵.md` 选择 `check-project-ready`、`check-skills`、Android 配置或相关文件 `git diff --check`，不默认全部执行。
3. 完整机器检查：`./scripts/gradlew-jdk17.sh testDebugUnitTest lintDebug assembleDebug`，只在里程碑、提交/发布准备、高风险变更或用户明确要求时执行。
4. 车机能力只读检查：`./scripts/check-device-capabilities.sh --package <普通第三方应用包名>`，仅在相关能力调查时使用且不改变设备。
5. 运行级效果由用户按 `docs/testing/验证矩阵.md` 手动体验；凡代码、资源、Manifest 或 Gradle 改动产生可手测行为，基础检查通过后由 AI 自动覆盖安装当前 Debug APK 并确认应用、进程和悬浮服务可启动。
